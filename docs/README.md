# 只读演示（公网可部署）

> ⚠️ **本目录兼作 GitHub Pages 的发布目录**，所以叫 `docs/` 而不是 `demo/`——
> GitHub Pages 的分支部署**只支持仓库根目录和 `/docs`** 两个位置，
> 叫 `demo/` 的话在 Pages 设置里根本选不到（实测踩过）。
> 这里放的是**演示快照**，不是项目文档；项目文档在仓库根目录（`ROADMAP.md` 等）。

一个**无需后端、无需 API Key、无需向量库**的静态演示：面试官点开链接就能看到系统
在各条链路上的真实输出——分层策略、引用来源、检索得分、禁忌拦截、拒答判定、工具计算。

## 为什么是「快照」而不是实时服务

实时版本需要三样东西，都不适合公开部署：

| 需要 | 问题 |
|---|---|
| 云端 LLM API Key | **不能公开**（会被盗刷） |
| Milvus Lite | **单进程独占**，多实例需换独立部署 |
| 常驻服务 | 持续成本，且冷启动慢 |

而演示的目的是**让人看到系统做了什么**，离线快照同样能做到——页面顶部会明确标注
「这是离线快照，不是实时服务」，不误导。

## 生成

```bash
python build_demo.py --list     # 先看会跑哪些问题
python build_demo.py            # 跑完整管线，生成 demo_data.json
```

产物：

```
docs/
├── index.html       # 自包含页面（无 CDN 依赖）
├── demo_data.json   # build_demo.py 生成的真实结果
└── README.md
```

> `demo_data.json` 已入库（它是产物，不是密钥）——这样即使不跑管线，页面也能直接打开。

本地预览：

```bash
cd docs && python -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899
```

## 部署（任选其一）

| 方式 | 步骤 | 成本 |
|---|---|---|
| **GitHub Pages**（推荐） | 仓库 Settings → Pages → Source 选分支，目录填 **`/docs`**（只有 `/` 和 `/docs` 可选） | 免费 |
| 阿里云 OSS / 腾讯云 COS | 开启静态网站托管，上传 `docs/` 两个文件 | 近乎免费 |
| HuggingFace Spaces | 选 Static 类型，上传同两个文件 | 免费 |
| Vercel / Netlify | 拖拽 `docs/` 目录 | 免费 |

部署后把链接放进简历/README 即可——**面试官不用 clone 仓库、不用配环境就能看到东西**，
这对学历不占优的候选人性价比很高。

## 页面展示了什么

| 用例类型 | 展示点 |
|---|---|
| 简单问答 | 分层策略走了快模型 + 短预算；答案后可展开**引用来源**与**检索得分** |
| 伤病问答 | 主模型 + 重排 + Fact-Check；答案更长、引用更多 |
| 禁忌拦截 | **生成前拒绝**——「腰突能做硬拉吗」给出禁忌原因，不给模型编造机会 |
| 工具计算 | BMI 由确定性函数算出并注入上下文，引用里带 `kind=tool` |
| 图谱检索 | 三路召回中图谱给出「伤病→动作」关系 |
| 问法重述 | 同一问题的不同措辞，检索稳定命中同一批文档 |
| 弱相关问题 | 含「健身」故相关度 0.52 → 如实说明无直接关联，而非硬编 |
| 无依据拒答 | 相关度 0.00 → 生成前拒答，不消耗一次生成 |

每张卡片都可展开「🔍 检索详情」，看到三路融合后每篇文档的**来源与得分**——
这是演示里最有说服力的部分：**不只是给结果，还给出中间过程**。
